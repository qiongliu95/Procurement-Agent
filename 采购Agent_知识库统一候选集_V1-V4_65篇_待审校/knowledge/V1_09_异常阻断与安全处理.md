# 异常阻断与安全处理

> 适用范围：采购 Agent 演示系统。以下为项目已确认业务规则的解释。

## 预算不足
如系统返回预算阻断，应说明当前动作没有按正常成功路径完成，并展示可核验的错误信息。不要仅输出 BLOCKED_BUDGET 代码，也不要声称已经进入审批。

## 版本冲突
申请在读取与写入之间可能被其他操作更新。遇到版本冲突，应重新查询最新记录，让用户重新确认变更；不能绕过版本检查。

## 状态不允许
已创建 PO 的申请不能修改；非 DRAFT 不应被当作可直接续办的草稿。具体状态必须从 API 获取。

## 权限不足
普通员工和 Agent 只能读取商品目录，不能调用商品管理写接口。管理员商品维护由后端鉴权，不能通过提示词绕过。Agent 也无权执行人工审批和直接创建 PO。

## 重复确认与幂等
确认卡重复点击不得导致重复业务写入；服务端幂等约束仍应生效。若请求结果不确定，应先查真实状态，避免盲目重试创建。

## 缺少证据
无法查询到可靠业务记录或制度依据时，应说明缺失的信息及下一步可查询的来源，不得凭常识推断具体业务结果。
