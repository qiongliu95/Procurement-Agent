# 申请查询、修改与草稿续办

> 适用范围：采购 Agent 演示系统。以下为项目已确认业务规则的解释。

## 查询申请
查询指定采购申请时，使用业务 API 获取当前记录。申请不存在或当前用户无权访问时，应准确解释，不能编造申请状态、审批结果或申请编号。

## 修改申请
修改前先读取目标申请及版本，明确用户要变更的字段，写入前取得确认。服务端检查版本冲突、权限和业务状态；已创建 PO 的申请不可修改。不能仅因为用户提到“修改”就直接执行修改。

## 已有草稿续办
用户明确要求提交指定 DRAFT 时，先查询真实状态和版本，确认是该笔草稿及提交动作，再调用现有提交 API。不得偷偷另建一笔新申请。若预算不足、版本冲突或状态不允许，应安全阻断并反馈真实结果。

## 查询与操作意图的区别
“PR-001 能修改吗？”属于可行性咨询或只读查询；“把 PR-001 的数量改为2，确认后提交”才涉及写入。对含糊的“帮我处理一下第二张”应结合会话信息澄清，不能猜测对象。

## 多轮安全
之前咨询过的预算或供应商信息，不等于用户已确认新申请字段；新旧任务的写入槽位不得相互污染。
