# 采购Agent RAG 知识评测 Case v1

## 评测对象与边界

- **共42条**：单条件10、复合条件10、跨文档综合10、证据不足6、知识/API路由6。不是知识库内容，不应入向量索引。
- 评测文档以你本地 `采购Agent_正式知识库_v1/manifest.csv` **实际放行的52篇及其修订正文为唯一标准**。
- 当前环境只能访问V1–V4原始65篇候选稿，无法读取本机Codex审校后52篇副本。因此文档ID是**预期证据定位候选**，不代表已确认进入52篇。尤其KB-002、KB-003、KB-010、PKB-V4-048已有正式修订，评分必须使用修订版本；本集没有采用这4篇的错误旧表述作为正确答案。所有Case初始状态均为“待匹配正式52篇manifest”。
- 只使用V1、V2、V4已知主题作预期证据，不以V3来源待补的品类技术描述构建强制正确答案。
- 题目中的金额、供应商名称、交货时间均为**提问输入条件**，不是真实数据库记录。涉及真实申请/商品/供应商/历史价格必须走API，未提供身份或无数据就澄清/拒答。

## 分类定义

1. **单条件**：一个规则或一个专业概念，重点看正确检索及直接回答；可能关联一篇文档。
2. **复合条件**：一个业务问题包含2个或更多并列、边界或排斥条件，需要完整作答；部分题的证据来自两篇文档，但主要判多条件覆盖。
3. **跨文档综合**：完整回答必须综合2—3篇**不同知识文档**的证据，不接受仅引用一篇并遗漏关键维度。
4. **证据不足**：检索分数高也不代表事实存在。拒绝编造公司规则、实际库存、违约金和实时行情。
5. **知识/API路由**：区分静态制度/通用建议与实时业务API，保证咨询无写入，操作走确认。

## 建议统一评分（后续一次性评估）

- **Retrieval Hit**：标注的参考文档至少一篇出现在Top-K；跨文档题另算 `Evidence Coverage = 命中的要求文档数 / 要求文档总数`。
- **Answer Coverage**：核对 `expected_answer_points` 里面的重要判断是否完整；不要仅以引用了ID就判对。
- **Groundedness**：回答的结论必须有对应检索证据、有效业务API结果或明确限定是通用建议。
- **Boundary & Routing**：不得触发 `forbidden_or_failure` 的行为；写入类必须遵守确认、后端权限和状态。
- **拒答是否正确**：无证据时不可把假设包装成确切结论；能部分回答时回答有证据部分并说清未知。
- **判定优先级**：对于P0的越权写入、绕过硬性规则、伪造实时业务数据，建议作为独立硬失败条件。最终权重由统一评估方案确定。

## 使用步骤

1. 本地Codex校验 `expected_doc_ids` 是否属于正式52篇；若某文档暂缓，标出Case为待调整而非误判模型失败。
2. 以正式文档修订版本确定黄金答案；任何表述与当前后端有效规则不一致，优先业务规则并更新测试期待。
3. 记录每条执行的query、top-k IDs、score、引文正文、回答、工具调用及是否写入；再集中评分分析。
4. 不需要每条单独调参，也不应该通过把测试问题原文塞回知识文档提升命中。
